DevOps & deploy

Production layout, verify-local, backups, migrations, and multi-worker ops.

What it does

Q: What does <code>briefr-doctor.sh</code> do?

A: Deploy script runs health/import checks and optional support pack download—operator diagnostics on the live box without manual curl juggling.

Q: What env vars matter for ops?

A: DATABASE_URL, JWT_SECRET, BRIEFR_REQUIRE_POSTGRES=1, RATE_LIMIT_ENABLED=1, BRIEFR_SCHEDULER_ENABLED, BRIEFR_RATE_LIMIT_STORE=db for multi-worker, BRIEFR_SETTINGS_KEY for encrypted settings.

Q: What is log rotation?

A: Deploy artifacts include logrotate configs for structured JSON logs—journald-friendly stderr from uvicorn.

Q: What license applies?

A: Apache 2.0—free for personal, commercial, and self-hosted use with attribution. SPDX headers in source trees.

Core implementation

Q: Is full docker-compose shipped?

A: Postgres compose exists (deploy/docker-compose.postgres.yml with pgvector image). All-in-one platform compose is planned—not the current production reference path.

Q: How do migrations run in deploy?

A: Alembic upgrade on deploy before uvicorn restart. Forward-only—roll forward fixes, never edit stamped revisions. Postgres apply required before merge for DDL changes.

Q: How do intel snapshots help DR?

A: Export/import bundles for allowlisted intel tables—versioned manifest, verify script, documented in OPERATIONS.md. Complements pg_dump backups, not a replacement.

Q: How do deploy scripts stay safe?

A: Additive compatibility promise in ROADMAP/OPERATIONS—deploy/ scripts run on live production boxes; changes must not break existing operator paths.

Q: What did deploy #745 add?

A: Production-zone install/deploy/service scripts under deploy/—additive compatibility promise for live boxes documented in OPERATIONS.md. Not a full platform docker-compose.

Q: What is corpus drift check?

A: POST /api/admin/diagnostics/corpus-drift regenerates security architecture generated layer to temp dir and diffs vs committed corpus—CI also runs test_security_architecture_corpus.py.

Integration

Q: What does production deployment look like?

A: Code at /opt/briefr, Postgres 16 often Docker at /opt/infra/postgres, nginx serving frontend/dist, systemd briefr-backend.service running uvicorn on :8000, age-encrypted backups under /var/lib/briefr/backups.

Q: How are backups handled?

A: Scheduled backup job plus deadman check. Postgres CI runs backup round-trip test. Admin UI exposes backup status; Download DB removed for Postgres—legacy SQLite export route remains dev-only.

Q: How is nginx configured?

A: Serves static frontend, proxies /api to uvicorn on localhost. TLS typically terminates at nginx or Cloudflare tunnel—not inside FastAPI.

Q: How is frontend released?

A: npm run build produces dist/ copied to nginx root on deploy. Vite dev server proxies /api only for development.

Q: What about Playwright smoke?

A: Gated behind PLAYWRIGHT_SMOKE=1 in verify-local full mode. Seeds SQLite and starts uvicorn + preview for UI smoke—optional locally.

Q: What is support pack export?

A: GET /api/admin/diagnostics/support-pack redacted health + ring-buffer logs; briefr-doctor.sh can download on live host—no secrets in bundle.

Performance

Q: How is Postgres sized?

A: No official sizing envelope published; architecture targets small VPS—CPU embeddings, single worker, bounded pool. Operators monitor admin Resources page and host disk I/O charts.

Security

Q: What is <code>verify-local.sh</code>?

A: Pre-merge gate mirroring CI: SQLite pytest, dependency audit, frontend build, unit tests, scoped lint. --full adds Postgres pytest, gitleaks, Playwright smoke. Green local verify suffices when GitHub Actions quota is exhausted.

Q: What CI jobs exist?

A: test, dependency-audit, frontend build, frontend unit tests; full adds Postgres tests, gitleaks (known red), Playwright smoke. dependency-audit and gitleaks are known non-blockers per CLAUDE.md.

Q: How do API-only workers deploy?

A: Multiple uvicorn instances behind nginx with BRIEFR_SCHEDULER_ENABLED=0; exactly one scheduler owner with =1. Shared DB rate-limit store mandatory for consistent auth/IOC limits.

Q: What production warnings fire at startup?

A: Posture self-check logs per unsafe flag when BRIEFR_ENV=production—rate limits off, insecure cookies, tokenless wallboard. Surfaced again in Admin Security panel.

Q: What would you check after a failed deploy?

A: Alembic version, health endpoint backend kind, scheduler owner flag, nginx proxy, JWT/auth login, feed row count, and application logs for migration or pool errors.
