Shared hooks, utils, and scoring helpers

The glue: hooks for async/watchlist/modals, utils for filters/links/presentation, and frontend scoring mirrors — patterns to learn, not a file dump of a hundred modules.

hooks/*.js hooks/useAsync.js hooks/useWatchlist.js hooks/useModalLayer.js utils/*.js utils/cveFilters.js utils/appLinks.js utils/correlationPresentation.js scoring/*.js api.js styles/tokens.css theme/ config/*.js components/*.jsx components/*.css components/DetailDrawer/*.jsx components/DetailDrawer/*.js components/DetailDrawer/*.css components/forge/*.jsx components/forge/*.js components/timeWindowDateUtils.js

Where logic goes when it is not a page

hooks/ holds reusable React behaviors (useAsync, useWatchlist, useModalLayer, visibility-aware intervals, inactivity timeout). utils/ holds pure or DOM-light helpers: CVE filtering, admin/analyst deep-links, correlation presentation, chart themes, display prefs. scoring/ mirrors server-facing constants the UI must display consistently. api.js is the fetch façade (errors carry requestId for operator grepping).

Pattern over inventory

The audit found ~100+ util files and ~130 components. Teaching every filename would be a phone book. The interview skill is: know the buckets, know when to add a util vs a component, and know that gate tests (*Gate.test.js) encode design-system regressions the CI suite actually runs.

How to navigate

Start from the user action → App.jsx / page → component → util/hook → api.js. If the behavior is presentation of server truth (priority bands, EPSS sparkline), look under utils/ or scoring/ before inventing a new formatter in a JSX file.

Self-check

  1. Give one example each of a hook vs a util vs a scoring helper — and why those three live in different folders.
  2. Why do many *Gate.test.js files exist under utils/ and admin pages?
  3. Where does an API error's requestId get attached for toast deep-links?
