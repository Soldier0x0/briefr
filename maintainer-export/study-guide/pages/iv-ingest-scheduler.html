Ingest & scheduler

APScheduler jobs, locks, api_queue, watermarks, and operator refresh honesty.

What it does

Q: What schedules recurring work?

A: APScheduler inside scheduler.py, started from FastAPI lifespan when BRIEFR_SCHEDULER_ENABLED=1. ~27 normal jobs plus optional registration-gated jobs (OTX continuous, exploit sources, detection LLM, SigmaHQ sync).

Q: Name core ingest jobs.

A: nvd_incremental_sync, kev_metadata_sync, epss_score_sync, weekly_mitre_refresh, vulnrichment_snapshot_sync, cvelistv5_incremental_sync—each writes canonical tables with watermarks.

Q: What startup one-shots exist?

A: Full ingest when CVE count < 10; deferred summary, EPSS history, exploit-source, and MITRE/ATLAS maintenance when data is sparse. These are not recurring cron entries but lifespan-triggered bootstrap.

Q: What jobs are registration-gated?

A: otx_continuous_sync, exploit_sources_sync, detection_context_llm, sigmahq_index_sync register only when their feature flags enable them. detection_context_llm needs restart to register.

Core implementation

Q: How are duplicate job runs prevented?

A: Each job uses max_instances=1, coalesce=True, and a per-job asyncio.Lock in scheduler_locks._LOCKS. Manual admin Run Now shares the same lock mapping via _JOB_RUN_MAP in routers/admin/jobs.py.

Q: How does stack backfill work?

A: STACK_BACKFILL_ENABLED opt-in historical NVD+KEV+EPSS for shallow stack coverage. Checkpointed per product with atomic claim_run_running gate. Procrastinate can defer resume after NVD rate limits.

Q: How are watchlist alerts emitted?

A: watchlist_monitor_alerts scheduler job detects KEV entry or EPSS/PoC changes on pinned CVEs and fires watchlist_alert webhooks. Snooze was removed from UI; pin/watchlist remains.

Q: What is CPE catalog sync (Q3)?

A: cpe_catalog_sync job (CPE_CATALOG_SYNC_ENABLED=0 default) populates software_catalog from NVD CPE 2.3 API with checkpointed full then incremental sync. Powers /api/stack/catalog/suggest typeahead.

Q: What is stack backfill idempotency (IDEM-A/B)?

A: claim_run_running atomic gate admits one worker; stale running reclaimed after STACK_BACKFILL_STALE_SECONDS. Procrastinate defer uses per-run queueing_lock; NVD 429 schedules durable resume after 180s when enabled.

Integration

Q: Explain the API queue serialization.

A: Outbound requests for rate-limited APIs enter a per-source queue. Health endpoint exposes task-level status. Background sync UI groups by provider and distinguishes waiting vs queued tasks.

Q: How do manual refresh routes interact with locks?

A: Admin Feed Health Sync and Scheduler Run Now call the same async locks as cron jobs so operators cannot double-run NVD or correlation jobs concurrently.

Q: What is catch-up mode v1?

A: Admin time-boxed backlog drain: raises embeddings/correlation caps + LLM pacing headroom; catchup_tick every 5 min nudges eligible work. Still respects api_queue and rate-limit floors.

Failure modes & edge cases

Q: What is feed health vs circuit health?

A: Feed health tracks sync freshness and last success per source. Circuit breaker state tracks consecutive failures for outbound HTTP. API key health probes are separate—they do not open/clear shared circuits used by real traffic.

Q: What retention jobs run?

A: cache_retention_cleanup sweeps stale ioc_cache/feed_cache, ages epss_history, OTX mirrors, ai_operations (30d), webhook logs, and crash-stranded webhook dedupe claims.

Q: How does OTX ingest behave on errors?

A: OTX pulses cache in feed_cache and mirror tables. Upstream 4xx/5xx serves any-age stale rows without deleting cached pulses—honest degradation for analysts.

Q: What is honest about FEED footer refresh timing?

A: Footer next refresh reflects nvd_incremental_sync only. Orphaned CACHE_REFRESH_* env vars are not scheduled—health refresh_schedule is null. No misleading auto-daily copy.

Q: How would you recover a stuck scheduler job?

A: Check Application logs with job_id + run_id from Scheduler table link, verify lock holder, inspect feed health circuit state, and use admin Run after upstream recovery. For stack backfill, stale running reclaims after STACK_BACKFILL_STALE_SECONDS.

Performance

Q: What does NVD incremental sync do?

A: Pulls modified CVEs from NVD API through the resilient client with circuit breaker and api_queue pacing. Commits core rows before optional enrichments. Respects API key headers when NVD_API_KEY is set.

Q: How does EPSS identity skip work?

A: Downloads the FIRST CSV.GZ, compares SHA256 and score_date to sync_state. Unchanged file skips gunzip, parse, and upsert—saving CPU on daily runs. Force via admin EPSS force-resync.

Q: What is catch-up mode?

A: Admin-only time-boxed backlog drain: raises embeddings/correlation caps and LLM pacing headroom. catchup_tick every 5 minutes nudges eligible work. Still respects api_queue, Retry-After, and rate-limit floors.

Q: What is <code>sigmahq_index_sync</code>?

A: Weekly default job mirrors SigmaHQ tarball into Postgres with commit+sha256 watermark. Admin can force re-sync clearing watermark. Detect tab prefers this local index over live GitHub search.

Q: How does metering relate to ingest?

A: API_CALL_EVENTS_ENABLED records every resilient_request attempt to api_call_events with source, latency, and actor/job IDs. Admin API keys page shows 24h breakdowns.

Q: How does EPSS identity skip save CPU?

A: Q5: compare downloaded CSV SHA256 + score_date to sync_state; unchanged file skips gunzip/parse/upsert. Force via admin EPSS force-resync.
