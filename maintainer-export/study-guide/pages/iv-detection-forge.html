Detection & Forge

SigmaHQ index, class router, DetectionContext, and Forge navigator workflows.

What it does

Q: What is <code>DetectionContext</code>?

A: Scaffold in feed_cache as detection_ctx:{cve_id} with CWE, product, class, artifacts, model metadata. Written by detection_context_sync job (default off) and Nuclei/LLM enrichers when enabled.

Q: What does Forge provide?

A: ATT&CK navigator matrix, hunt packs, threat scenarios, proof bench, KEV backlog, and coverage views. Top tabs switch views; matrix click toggles technique selection. Hunt pack generation shares detection engine with Detect tab—no LLM required.

Q: What is detection composer status?

A: DC-1…DC-4 shipped for evidence pack and emit Sigma/SIEM/YARA via shared engine. Broader composer UX may expand, but core emit paths are live in Detect and Forge generate.

Q: What is community-Sigma-first policy?

A: Detect prefers community SigmaHQ rules over generated BRIEFR templates when CVE-exact matches exist. Reduces noise and respects SigmaHQ authorship with Show YAML and attribution strings.

Q: What ATT&amp;CK navigator UX shipped (PM-4d)?

A: Top view tabs; tactic columns with id + name; click toggles selection; hunt pack only on coverage view. Removed GAP/COMMUNITY/YOURS chrome for clarity.

Q: What tests cover detection?

A: test_sigmahq_index.py, test_sigmahq_index_read.py, class router tests, and admin job map tests ensure scheduler wiring matches run_sigmahq_index_sync.

Q: What Forge views exist beyond the matrix?

A: Threat scenarios, proof bench, KEV backlog (?view=backlog), hunt packs, coverage—top tabs switch views; matrix click toggles technique selection (PM-4d).

Core implementation

Q: Explain BRIEFR class templates.

A: Deterministic templates keyed by ATT&CK technique when mapped, else CWE (briefr_basis), never generic dumps. class_router.py resolves class consistently for Sigma, SIEM, and log patterns.

Q: How does KEV backlog appear?

A: Scheduler kev_backlog_reconcile and detection/backlog.py emit kev_backlog notifications deep-linking to Forge ?view=backlog. Surfaces gaps between KEV and detection coverage.

Q: How do artifacts merge from Nuclei?

A: DETECTION_CONTEXT_NUCLEI_ENABLED=1 default parses Nuclei YAML on exploit sync into detection context; merges keywords/paths into emitted BRIEFR templates when present.

Q: What did detection composer DC-1…DC-4 ship?

A: Evidence pack + emit Sigma/SIEM/YARA via shared detection engine—no LLM required. Detect tab and Forge hunt-pack generate share the same class router and SigmaHQ index path.

Q: How does YARA generation use IOC structs?

A: Deterministic from structured IOC type/value in detection context—test_yara_generator.py guards shapes. Not LLM-invented strings.

Integration

Q: How does Forge link to the drawer?

A: Drawer MITRE section pivots to Forge navigator; hunt-pack CVE chips open the drawer. URL sync uses ?tab=forge plus view/technique params with history push for back button.

Q: What SIEM outputs exist?

A: Class-aware queries selected by class_router—same class as Sigma and log patterns. Export paths live in detection module consumed by Detect UI and Forge hunt-pack generate.

Q: How does kev_backlog notification deep-link?

A: Scheduler detection/backlog.py emits kev_backlog to user_notifications; analyst bell opens Forge backlog view for stack coverage gaps.

Failure modes & edge cases

Q: How is Forge coverage honest?

A: Empty/sparse matrix uses shared EmptyState—no forced tall black columns. Campaign clusters avoid 'ranked for your stack' without stack pins. Wallboard distinguishes global vs stack-scoped empty copy.

Q: How are detection flags configured?

A: Admin config exposes DETECTION_CONTEXT_* and SIGMAHQ_INDEX_SYNC_* with honest apply strategies—immediate vs restart for LLM job registration.

Performance

Q: What is the Detect tab's purpose?

A: Surface detection content for a CVE: community Sigma rules from the local SigmaHQ index, BRIEFR class templates when appropriate, SIEM queries, and log patterns—driven by a unified class router so all three agree on class.

Q: How does SigmaHQ indexing work?

A: sigmahq_index_sync mirrors the SigmaHQ tarball into Postgres with commit and SHA256 watermark. find_sigma_rules prefers CVE-exact local matches with DRL attribution. Live GitHub search is fallback only when index empty.

Q: What is <code>match_basis</code> honesty?

A: UI distinguishes never-synced index, empty index, no CVE-exact match, and community vs BRIEFR template sources. BRIEFR YAML is suppressed when community hits exist or template would be generic.

Q: Can Forge generate without cloud AI?

A: Yes—hunt pack generate and detection emit paths are deterministic from structured CVE context and Sigma index. LLM is optional overlay for richer artifacts, not a gate.

Q: How does Detect relate to IOC tab?

A: IOC tab is live enrichment lookup (VT, AbuseIPDB, GreyNoise)—separate from rule generation. Detection uses persisted CVE context and Sigma index, not IOC query results directly.

Q: How would you demo Detect in an interview?

A: Open a KEV CVE with Sigma index synced—show community rules with attribution, contrast with CWE-based BRIEFR template on unmapped technique, and pivot to Forge matrix for coverage context.
