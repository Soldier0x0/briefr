Product, behavioral & solo owner

Roadmap judgment, trade-offs, and maintainer narrative in first person.

What it does

Q: What metric would you track if you had more time?

A: Time-to-triage for stack-matched KEV CVEs—proxy via feed sort + OP accuracy feedback. Today we expose operational signals (backlog notifications, feed health) more than product analytics.

Core implementation

Q: Tell me about UX debt you paid down.

A: Forge honesty PRs: no fake 'ranked for your stack', real EmptyState on sparse ATT&CK matrix, community-Sigma-first Detect. I treat analyst trust as a feature—wrong detection is worse than no detection.

Q: How do you onboard a new contributor quickly?

A: CLAUDE.md rulebook, HANDOVER newest-first, graphify/study-guide for architecture. Danger zones call out scheduler lock strings, migration forward-only, and request-path heavy work prohibition.

Integration

Q: Describe coordinating UI and backend changes.

A: ADR-002 scoring shipped API-first—frontend displays /risk only. Drawer bundle reduced chatty fetches. I resist duplicating business logic in React; it always drifts.

Failure modes & edge cases

Q: Describe a production incident mindset you encoded.

A: RCA-first: reproduce, trace end-to-end, fix the class of bug, add a regression test. Example: FE refresh dedupe—concurrent 401s could revoke all sessions; shared in-flight refresh fixed the structural race, not just retry logic.

Q: How do you say no to features?

A: STIX export excluded from current loop, light theme removed, snooze removed, Investigation Score removed—documented non-goals. I prefer deleting misleading UI over maintaining half-honest paths.

Q: How do you design for self-hosters with no API keys?

A: Core CVE feed, RSS, and search work offline from public feeds. Empty states explain missing VT/GreyNoise keys without looking broken. Keys enhance; they do not gate login.

Q: How do you decide when to add Procrastinate vs APScheduler?

A: Durable when failure is expensive and retry semantics matter—stack backfill, LLM product extraction. Cron ingest stays APScheduler with locks—simpler mental model for operators.

Q: Where is BRIEFR headed next?

A: Durability tail (PR-R series), formal resource benchmarking, detection composer expansion, and honest platform compose—while keeping single-server deploy the default story.

Performance

Q: How do you manage LLM cost risk?

A: Router failover, pacing headroom, empty-payload skip, ai_operations metering without storing prompts. LLM defaults off for detection context; deterministic Nuclei path default on.

Security

Q: How do you prioritize the roadmap?

A: docs/PRODUCT_STATUS.md and docs/planning/SPRINT_2026-07.md drive truth. I ship operator pain first—auth hardening, scheduler honesty, feed performance—before greenfield features like full platform compose.

Q: How do you handle docs vs code drift?

A: PRODUCT_STATUS wins over README snapshots. I update SYSTEM_DESIGN and API_REFERENCE in the same PR as behavior changes. Corpus drift check in admin compares generated security architecture to committed files.

Q: How do you handle security findings?

A: Fail closed in production: JWT required, admin key removed, SSRF blocks expanded, session revalidation. Security posture page gives analysts read-only transparency without duplicating admin corpus editing.

Architecture tradeoffs

Q: Why build BRIEFR as a solo maintainer project?

A: I wanted analyst-grade CVE triage without SIEM cost or SaaS data residency concerns. A monolith with honest self-host docs matches how small teams actually deploy—one Postgres, one operator, incremental flags instead of microservice sprawl.

Q: Tell me about a hard technical trade-off you made.

A: I kept APScheduler in-process instead of jumping to Celery everywhere. Procrastinate is optional for a narrow durable queue. That trades theoretical scale for operability—one lock map, one admin Scheduler page, predictable failures.

Q: Why Apache 2.0?

A: Maximum adoption for defenders who cannot ship GPL contagion into commercial SOCs. Clear NOTICE attribution; aligns with SigmaHQ and ecosystem tooling expectations.

Q: What is your testing philosophy?

A: Default SQLite pytest for speed; Postgres path before merging db/ changes. verify-local as merge gate. Playwright smoke optional. Tests assert behavior operators see—job lock maps, EPSS skip, Sigma index read path.

Q: What would you do differently starting over?

A: I might stamp Postgres-only earlier—but SQLite test fallback still saves CI minutes. I'd also centralize model catalog from day one; we recovered from stale OpenRouter IDs with SSOT in model_catalog.py.

Q: Why dark terminal aesthetic?

A: Analysts live in terminals and SOC walls; light mode was noise. Tokens and Radix gave accessibility without Material blandness. Density-first—no hero marketing columns.

Q: Why relicense to Apache 2.0 (#748)?

A: OSI-approved, commercial-friendly, aligns with SigmaHQ/ecosystem expectations—removed BSL/BUSL confusion for self-hosters and contributors.

Q: Why migrate study guide to briefr-maintainer (#751)?

A: Public repo stays product-focused; deep maintainer/onboarding docs live private. Interview pack ships as maintainer-export/ portable drop-in.
