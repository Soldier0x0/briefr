API & operations

Health, admin diagnostics, webhooks, notifications, and structured logging.

What it does

Q: What admin diagnostics exist?

A: Support pack export, corpus drift check, DB integrity probe, retrieval health, API usage metering, and application log ring buffer filtered by job/run id.

Q: How is config applied?

A: GET /api/admin/config/schema exposes apply_strategy: immediate, scheduler_reschedule, or restart. Interval saves reschedule APScheduler triggers without full process restart when possible.

Q: What metering endpoints exist?

A: GET /api/admin/api-usage/metering for 24h by-source and by-actor breakdown from api_call_events. Complements API key health probes.

Q: What structured logging fields help ops?

A: JSON logs: ts, level, request_id, briefr.access lines with duration_ms. Job context adds job_id and run_id in scheduler runs.

Q: What is intel snapshot export?

A: scripts/export_intel_snapshot.py allowlisted tables per DATA_SNAPSHOT.md with manifest version 1. Import/verify scripts support migration between instances—operator tooling, not daily API.

Core implementation

Q: How do webhooks work?

A: Database-backed destinations with per-destination event subscriptions, dedupe keys, delivery log, and health cards. Scheduler emits watchlist, KEV backlog, and operator events. Test POST works on disabled destinations.

Q: How does stack catalog suggest work?

A: GET /api/stack/catalog/suggest (≥3 chars) typeahead from software_catalog when CPE catalog sync enabled—merged with curated lists in asset wizard.

Integration

Q: What does <code>/api/health</code> expose?

A: Backend kind (postgres/sqlite), scheduler enabled flag, refresh schedule honesty, outbound queue per source, and dependency readiness. Frontend polls for restart banner and onboarding checklist.

Q: How are errors returned?

A: Expected 4xx: HTTPException with short safe detail. Unexpected: generic 500 JSON with request_id; full traceback only in structured logs. Frontend shows detail plus X-Request-ID ref line.

Q: What is the drawer bundle endpoint?

A: GET /api/cves/{id}/drawer orchestrates parallel sub-fetches—each uses its own DB connection. Reduces round trips for DetailDrawer tabs while staying asyncpg-safe.

Q: What is the notification center?

A: user_notifications backs analyst bell (watchlist, KEV backlog) and admin StatusBar bell (job errors, unhealthy keys, webhook failures). Open marks seen; dismiss with undo.

Q: How would you version breaking API changes?

A: BRIEFR favors additive JSON fields and feature flags. Breaking changes require PRODUCT_STATUS, API_REFERENCE, and frontend contract tests updates in the same PR—deploy scripts promise additive compatibility.

Failure modes & edge cases

Q: How does semantic search API behave?

A: /api/search/semantic accepts query plus filters; returns typed sections for techniques, campaigns, CVEs when embeddings enabled. Empty embeddings gracefully degrade.

Performance

Q: How does keyset pagination work?

A: GET /api/cves supports pagination=keyset for stable large-feed traversal alongside legacy offset if present. Pair with server-side stack relevance sort for personalized feeds.

Security

Q: How is the API organized?

A: FastAPI routers under routers/: analyst CVE/feed/search, auth, me/preferences, IOC, Forge, wallboard, admin packages. ORJSON default response class for speed. Global exception handler returns generic 500 with request_id.

Q: What auth middleware applies?

A: Session middleware validates briefr_at cookie on analyst /api/*. Admin routes check admin role. Wallboard routes accept header token. LLM summary endpoints require logged-in user.

Q: What rate limits apply to admin?

A: Token buckets on destructive or expensive routes—e.g., DB explorer 30/min. Refresh and auth endpoints have dedicated limits to prevent brute force and token stuffing.

Q: How is wallboard API secured?

A: X-BRIEFR-Wallboard-Token header required; optional config token. No query-string token. Ranked tiles use OP then Threat fields.

Q: Are there public unauthenticated APIs?

A: Health may be open for load balancers; analyst intel routes are not. Setup route only before first user exists. Self-hosted assumes trusted network or edge auth for defense in depth.
