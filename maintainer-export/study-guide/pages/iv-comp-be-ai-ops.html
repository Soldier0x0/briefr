Backend · AI, ML & operations

AI/ML, webhooks, wallboard, backup, monitoring, onboarding.

What it does

Q: What does `backend/ai/gemini_client.py` do?

A: Google Gemini generateContent client.

Q: What does `backend/ai/groq_config.py` do?

A: Shared Groq API settings for all BRIEFR LLM call sites.

Q: What does `backend/ai/llm_pacing.py` do?

A: Shared LLM provider pacing — RPM/TPM headroom for outbound API queue spacing.

Q: What does `backend/ai/llm_payload.py` do?

A: Outbound LLM request payload validation — skip API calls when there is nothing to send.

Q: What does `backend/ai/llm_router.py` do?

A: Task-based multi-provider LLM router with failover (Track K2). Failover order per task — not round-robin. One attempt per provider per call; never parallel-call the same CVE on multiple providers.

Q: What does `backend/ai/llm_session.py` do?

A: Per-job LLM provider session — skip providers that returned empty after failover.

Q: What does `backend/ai/model_catalog.py` do?

A: Model catalog SSOT for LLM task → provider failover chains (AI-1).

Q: What does `backend/ai/openai_chat.py` do?

A: OpenAI-compatible chat completion helper (Groq, Cerebras, OpenRouter).

Q: What does `backend/ai/operations_admin.py` do?

A: Admin payloads for AI Operations (AI-2).

Q: What does `backend/ai/operations_recorder.py` do?

A: Record LLM completion attempts to ai_operations (AI-1).

Q: What does `backend/ai/quota.py` do?

A: Advisory LLM provider quota snapshots from rate-limit response headers.

Q: What does `backend/ai/summary.py` do?

A: Executive summary for PDF reports — multi-provider LLM router, template last. Called only when an analyst explicitly exports a PDF (via API from the client).

Q: What does `backend/backup/__main__.py` do?

A: CLI: python -m backup [run|list|restore|verify|ensure|keygen]

Q: What does `backend/backup/manager.py` do?

A: Database backup manager for BRIEFR (SQLite and PostgreSQL). SQLite: - Online backup via sqlite3.Connection.backup() (WAL-safe) - PRAGMA integrity_check before and after each backup - Automatic restore on startup when the live DB fails integrity check PostgreSQL (when DATABASE_URL is set): - pg_dump custom-format archive (briefr.pgdump inside the tarball) - pg_restore on manual restore (--clean --if-exists) Both backends: - Tar archives with optio

Q: What does `backend/backup/postgres_util.py` do?

A: PostgreSQL backup helpers (pg_dump / pg_restore) for backup.manager.

Q: What does `backend/diagnostics/support_pack.py` do?

A: Builds redacted operator support-pack ZIP (health + ring-buffer logs).

Q: What does `backend/ml/embeddings.py` do?

A: CVE description embeddings — env-gated, CPU-only (V1.3 / E2–E3). **Write path (E2):** dual-write to ``embeddings`` + legacy ``cve_embeddings``. **Related (E3):** request path uses stored vectors only — pgvector ANN (or SQLite BLOB cosine) on ``embeddings``, then legacy ``cve_embeddings`` NumPy scan. No model inference for related. **Semantic search (E3):** may embed a single query string when ``EMBEDDINGS_ENABLED=1`` (design §7.1). Bulk corpus em

Q: What does `backend/ml/product_extraction.py` do?

A: LLM product extraction for NVD-unanalyzed CVEs - env-gated (V1.3). Many fresh CVEs carry no CPE data for hours or days. When ``LLM_PRODUCT_EXTRACTION_ENABLED=1`` AND at least one LLM provider API key is set, a scheduler job extracts ``{vendor, product, version_range}`` from the description text and fills ``affected_products`` - ONLY while that field is empty - marking ``affected_products_source='llm'`` so the data stays distinguishable. Q: What does `backend/monitoring/api_key_health.py` do?

A: Lightweight API key health pings for operator monitoring (Issue 21).

Q: What does `backend/monitoring/notifications.py` do?

A: Operator notification center — durable events from audit log and monitors.

Q: What does `backend/notifications/emit.py` do?

A: Emit in-app notifications when monitor rules fire.

Q: What does `backend/onboarding/checklist.py` do?

A: First-hour operator onboarding checklist (Wave 4). Copyright © 2026 Sai Harsha Vardhan SPDX-License-Identifier: Apache-2.0

Q: What does `backend/services/retrieval_health.py` do?

A: Admin retrieval / embeddings index health (post-E8 ops honesty). Copyright © 2026 Sai Harsha Vardhan SPDX-License-Identifier: Apache-2.0

Q: What does `backend/services/semantic_search.py` do?

A: Hybrid semantic search orchestration over embeddings + filters (E3/E8).

Q: What does `backend/services/stack_backfill_worker.py` do?

A: Process Tier A stack backfill runs (Q4). NVD keyword pages → upsert_cves → EPSS filter apply → KEV flag match. Never calls OTX / exploits / correlation.

Q: What does `backend/wallboard/service.py` do?

A: Wallboard aggregated payload (Beta V1.4 Theme 4). Read-only intel posture tiles built from existing DB state and cached snapshots — no outbound HTTP, no admin data, no secrets. Copyright © 2026 Sai Harsha Vardhan SPDX-License-Identifier: Apache-2.0

Q: What does `backend/wallboard/session.py` do?

A: Signed httpOnly wallboard session cookies — never stores raw WALLBOARD_TOKEN.

Q: What does `backend/webhooks/alerts.py` do?

A: KEV-on-stack and backup dead-man alert rules (V1.3 Theme 8, V1.4 engine).

Q: What does `backend/webhooks/destinations.py` do?

A: Webhook destination configuration — env seeds plus DB overrides (V1.4).

Q: What does `backend/webhooks/engine.py` do?

A: Multi-destination webhook dispatch engine (V1.4 Theme 2).

Q: What does `backend/webhooks/sender.py` do?

A: Send alert messages via the V1.4 webhook engine. Destinations are configured through env vars and/or the webhook_destinations table. When no destination is configured, send_alert is a no-op.

Q: What does `backend/webhooks/ssrf.py` do?

A: SSRF protections for outbound webhook HTTP (V1.4 Theme 2). Validates destination hostnames/IPs before connect, pins resolved IPs on the wire (Host header preserved), allows https only, disables redirects, and never attaches internal API secrets to outbound headers.
