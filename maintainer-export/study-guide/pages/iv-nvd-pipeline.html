NVD ingestion & feed pipeline

Resilient client, incremental sync, transaction boundaries, and operator refresh paths.

What it does

Q: What is the NVD pipeline's job in BRIEFR?

A: Pull modified CVE JSON from NIST NVD into the canonical cves table, then commit before optional enrichments (CIRCL, Sploitus, etc.). Watermarks in sync_state make incremental runs idempotent. Analyst FEED and DetailDrawer read only persisted rows—never live NVD on every page view.

Q: Which modules own NVD ingest end-to-end?

A: Scheduler job nvd_incremental_sync in scheduler.py calls ingest helpers under ingest/nvd/ (and related feed code). HTTP uses services/resilient_client.py via api_queue pacing. Persistence is db/cves.py with db/txn_boundaries.py separating writer transactions from slow enrich.

Core implementation

Q: How does incremental NVD sync choose what to fetch?

A: The job reads the last successful modified cursor/window from sync_state, requests CVEs changed since that point through the NVD 2.0 API, upserts core fields, then advances the watermark only after a successful commit. Full bootstrap on empty DB (<10 rows) uses a broader initial pull from lifespan startup.

Q: What does the resilient HTTP client add beyond requests?

A: resilient_request applies per-source retry policy, records failures for circuit health, respects Retry-After, and logs attempts to api_call_events when metering is enabled. Non-retryable 4xx fail fast without tripping the circuit; repeated 5xx/open circuit fails fast until cooldown.

Q: How is NVD API key usage handled?

A: NVD_API_KEY from process env (wins over .env) is sent on outbound NVD calls for higher rate limits. Missing key still works—slower pacing. API key health probes are separate from the traffic circuit so a bad probe does not poison real ingest.

Q: Why commit NVD core rows before enrichments?

A: txn_boundaries.py prevents CIRCL/Sploitus enrich from holding the same long writer connection as bulk NVD upsert. Slow enrich cannot exhaust the pool and block feed reads. This is a structural fix for 'ingest wedged the app' incidents, not a retry band-aid.

Q: What is cvelistV5 sync vs NVD incremental?

A: cvelistv5_incremental_sync mirrors the CVEList v5 git corpus for fields/auxiliary metadata NVD may lag on. It is a sibling job with its own watermark—not a replacement for NVD modified feed.

Q: How does vulnrichment snapshot sync fit?

A: vulnrichment_snapshot_sync ingests CISA vulnrichment SSVC snapshots into satellite tables consumed by /risk SSVC paths. Scheduled separately from NVD modified API with its own health row.

Q: Where are NVD field mappings maintained?

A: Ingest parsers map NVD 2.0 JSON into cves columns and JSON blobs (CPE, references). Changes require pytest coverage on sample fixtures and Postgres apply for any new columns via Alembic.

Q: How does metering attribute NVD calls to jobs vs users?

A: resilient_request passes actor metadata—scheduler jobs include job_id/run_id in logs and api_call_events when enabled. Analyst-triggered paths use request context. Admin usage page breaks down by actor.

Integration

Q: How does NVD ingest connect to scoring and OP?

A: Upserted CVSS, CWE, affected products, and publication dates feed POST /api/cves/{id}/risk on next read. KEV/EPSS jobs are separate schedulers but join on cve_id. FEED cards do not recompute Threat client-side—they display API fields after NVD+satellite data lands.

Q: How do admin Feed Health actions trigger NVD sync?

A: Feed Health 'Sync' and Scheduler 'Run now' for nvd_incremental_sync call the same async lock as cron via _JOB_RUN_MAP. Operators cannot double-run NVD concurrently with cron or another manual run.

Q: How does stack backfill relate to NVD?

A: STACK_BACKFILL_ENABLED triggers historical NVD+KEV+EPSS pulls per product checkpoint. When NVD rate-limits, Procrastinate can defer resume. Backfill shares resilient client and metering but uses its own run gate (claim_run_running).

Q: How does FEED footer refresh honesty relate to NVD?

A: Footer next refresh reflects nvd_incremental_sync schedule only—orphaned CACHE_REFRESH_* env vars are not wired. Health refresh_schedule null when disabled so UI does not promise phantom auto-refresh.

Q: How do embeddings auto-on-ingest interact with NVD?

A: When EMBEDDINGS_AUTO_ON_INGEST is on, new/changed CVE rows from NVD enqueue embed work on ingest path—capped per run. Semantic search stays retrieval-only; NVD text is not sent to LLM providers for scoring.

Q: How does MITRE weekly refresh interact with NVD CPE data?

A: weekly_mitre_refresh updates ATT&CK/ATLAS corpora used by Forge and technique embeddings—not a substitute for per-CVE NVD upsert. Technique links in drawer consume both corpora and CVE affected-product fields.

Failure modes & edge cases

Q: What happens when NVD returns 503?

A: Transient 503s are retried per resilient client policy; sustained failures increment circuit health and surface on Feed Health with circuit-open state. FEED continues serving last committed Postgres rows—no empty wipe. Operators retry after cooldown or use admin reset-circuit when upstream recovers.

Q: How do you debug a stuck NVD job?

A: Scheduler table links to Application logs filtered by job_id=nvd_incremental_sync and run_id. Check api_queue depth on /api/health, verify lock not held by dead task, inspect sync_state watermark, and confirm Postgres pool not saturated.

Q: What if the watermark advances but rows are missing?

A: RCA path: compare NVD API response count vs upsert count in logs, check for transaction rollback after partial batch, verify Alembic schema matches ingest expectations. Recovery is forward-only re-sync or targeted admin force paths—not editing applied migrations.

Q: How does catch-up mode affect NVD?

A: Catch-up raises caps for embeddings/correlation/LLM—not a bypass of NVD rate limits. NVD still obeys api_queue and circuit breaker; catch-up tick nudges eligible backlog jobs without duplicating cron owners.

Q: What regression tests guard NVD ingest?

A: test_resilient_client.py (circuit/retry), NVD txn boundary tests, scheduler job map tests, and feed health routes. Any db/ SQL change needs SQLite default + Postgres --full run before merge.

Performance

Q: How does api_queue protect NVD rate limits?

A: Outbound NVD calls serialize through the per-source queue so concurrent drawer refreshes and cron do not stampede the API. Health exposes waiting vs active tasks; Background sync UI groups by provider.

Q: What DB patterns keep NVD ingest fast?

A: Batch upserts, short transactions for core CVE rows, separate connections for parallel read paths, KEV join indexes, and keyset pagination on feed endpoints. Long enrich runs outside the critical NVD commit path.

Q: How is API metering used for NVD ops?

A: API_CALL_EVENTS_ENABLED logs each resilient_request with source=nvd, latency, actor job id. Admin API usage page shows 24h breakdowns to spot quota burn vs circuit trips.

Security

Q: What trust boundary applies to NVD data?

A: NVD JSON is treated as untrusted input: parsed into typed fields, size-bounded HTTP, no eval. SSRF protections apply to other outbound fetches; NVD uses fixed NIST endpoints. No operator-supplied URL in the NVD path.

Q: Can analysts trigger arbitrary NVD replay?

A: Only admin role can Run Now or Feed Health sync. Analyst routes are read-only on CVE tables. Rate limits and job locks prevent abuse of operator actions.

Architecture tradeoffs

Q: Why not fetch NVD live per CVE in the drawer?

A: Request-path NVD would couple analyst latency to NIST availability, break rate limits, and bypass scoring consistency. Persisted ingest with honest stale indicators matches self-hosted ops reality—one scheduler owner, predictable DB reads.

Q: Why incremental sync instead of nightly full export?

A: Full export is network- and CPU-heavy for small VPS targets. Incremental modified feed plus bootstrap on empty DB balances freshness with operator hardware. Stack backfill is opt-in for historical depth.

Q: Why not use Procrastinate for all NVD pulls?

A: NVD incremental is cron-shaped with in-process locks—operators already understand APScheduler + Feed Health. Procrastinate adds value for durable resume (stack backfill) where retry semantics justify Postgres queue overhead.
