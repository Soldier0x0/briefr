Backend · feeds

All <code>backend/feeds/*.py</code> ingest modules.

What it does

Q: What does `backend/feeds/ai_context.py` do?

A: AI/ML CVE context detection and MITRE ATLAS technique hints.

Q: What does `backend/feeds/atlas.py` do?

A: MITRE ATLAS — AI/ML adversarial threat landscape (separate from Enterprise ATT&CK).

Q: What does `backend/feeds/case_study_feed.py` do?

A: Combined Incidents & News feed — RSS + ATLAS served from a precomputed snapshot.

Q: What does `backend/feeds/cpe_catalog.py` do?

A: NVD CPE 2.3 dictionary sync → software_catalog (Q3). Runs on the scheduler (never the request path). Uses resilient_get("nvd") so pacing + Q2 metering apply. Full corpus is checkpointed across runs.

Q: What does `backend/feeds/cve_record_v5.py` do?

A: Parse CVE JSON 5.x records (cvelistV5 / vulnrichment) into BRIEFR CVE dicts.

Q: What does `backend/feeds/cvelistv5.py` do?

A: cvelistV5 — CVE JSON 5.x records hours before NVD. Incremental sync via GitHub compare API; watermark stored in sync_state as ``cvelistv5_head_sha``. Only changed JSON paths are fetched each run.

Q: What does `backend/feeds/epss.py` do?

A: Product module backend/feeds/epss.py (epss).

Q: What does `backend/feeds/errors.py` do?

A: Feed-layer errors surfaced to scheduler job status (ERR-001).

Q: What does `backend/feeds/exploit_common.py` do?

A: Shared helpers for scheduler-side exploit-availability feeds.

Q: What does `backend/feeds/exploit_sync.py` do?

A: Orchestrates ExploitDB, Metasploit, Nuclei index, and PoC-GitHub exploit feeds under exploit_sources_sync.

Q: What does `backend/feeds/exploitdb.py` do?

A: ExploitDB CSV snapshot sync.

Q: What does `backend/feeds/extended.py` do?

A: Extended threat-intelligence feeds — each answers a question existing sources do not. Sploitus: public exploit listings per CVE (not covered by NVD reference tags alone). GreyNoise: internet-wide scanning context for IPs (not VT/AbuseIPDB). MalwareBazaar: malware family for file hashes (not VT classification). URLhaus: URL/domain malware hosting (not VT domain stats). CIRCL CVE-Search: supplemental references, CAPEC, vendor advisories.

Q: What does `backend/feeds/file_identity.py` do?

A: Whole-file feed identity helpers (Q5). Reusable for EPSS CSV today and CTID/other bulk files later: store ``{score_date, sha256}`` in sync_state after a successful apply; matching sha256 skips decompress/parse/apply on the next run.

Q: What does `backend/feeds/github_helpers.py` do?

A: Shared GitHub API helpers for repo-based intel feeds.

Q: What does `backend/feeds/incident_news.py` do?

A: Fetches and normalizes cybersecurity RSS sources for Incidents & News tab.

Q: What does `backend/feeds/incident_sources.py` do?

A: Config for Case Studies incident/news RSS sources.

Q: What does `backend/feeds/kev.py` do?

A: Product module backend/feeds/kev.py (kev).

Q: What does `backend/feeds/metasploit_modules.py` do?

A: Metasploit module metadata snapshot sync.

Q: What does `backend/feeds/mitre.py` do?

A: MITRE ATT&CK Enterprise STIX + CTID CVE→technique mappings.

Q: What does `backend/feeds/nuclei_index.py` do?

A: Nuclei templates CVE index snapshot sync.

Q: What does `backend/feeds/nvd.py` do?

A: Product module backend/feeds/nvd.py (nvd).

Q: What does `backend/feeds/osv.py` do?

A: Product module backend/feeds/osv.py (osv).

Q: What does `backend/feeds/otx.py` do?

A: AlienVault OTX — campaign correlation via community pulses. CVE pulses: threat intel collections referencing a vulnerability. Pulse IOCs: indicators bundled in a pulse (IPs, domains, hashes). IOC lookup: pulses referencing an indicator + CVE pivot links.

Q: What does `backend/feeds/otx_continuous.py` do?

A: Continuous OTX background sync — spends hourly API budget across the day. Runs on a short interval (default 5 min) and uses up to OTX_CONTINUOUS_BUDGET_PER_RUN API calls per invocation for CVE pulse fetch + pulse IOC prefetch. Pacing (2 req/sec) and hourly quota gates are enforced by api_queue + tracking.has_quota.

Q: What does `backend/feeds/poc_github.py` do?

A: PoC-in-GitHub index sync (nomi-sec/PoC-in-GitHub). Repo pull with commit watermark; merges exploit rows and sets has_poc additively.

Q: What does `backend/feeds/threatfox.py` do?

A: ThreatFox bulk IOC ingest (abuse.ch Auth-Key).

Q: What does `backend/feeds/vulncheck_kev.py` do?

A: VulnCheck community KEV catalog sync (V1.5 Theme 4b).

Q: What does `backend/feeds/vulnrichment.py` do?

A: CISA Vulnrichment — SSVC / CVSS / CWE / CPE for NVD-unanalyzed CVEs. Snapshot-style sync (no watermark): each run lists the repo tree and enriches CVE rows that still lack official NVD analysis fields. CISA ADP data is superseded when NVD later fills cvss_score / severity / cwe_ids.
