Backend · database

All <code>backend/db/*.py</code> modules.

What it does

Q: What does `backend/db/ai_operation_payloads.py` do?

A: Opt-in storage for failed LLM request payloads (Program E).

Q: What does `backend/db/ai_operations.py` do?

A: Persist redacted LLM operation rows (AI-1). Postgres-native with SQLite parity.

Q: What does `backend/db/api_metering.py` do?

A: Outbound API call event persistence (Q2). Failures must not break callers.

Q: What does `backend/db/app_settings.py` do?

A: Operator settings persisted in PostgreSQL/SQLite (Phase B). Keys mirror writable admin config (`config_schema.WRITABLE_CONFIG_KEYS`). Process environment variables set before startup always win over DB values.

Q: What does `backend/db/cache.py` do?

A: IOC cache, feed cache, exploit storage. Split from database.py (Phase 3). Postgres-native (Post-B Phase 1): queries use explicit ``$n`` placeholders on Postgres and ``?`` on SQLite — no reliance on ``db/dialect.py`` regex translation for this module.

Q: What does `backend/db/cache_retention.py` do?

A: Physical retention sweeps for cache and overlay tables (Sprint C3). Read paths enforce TTL via ``cached_at`` / ``fetched_at`` filters; this module deletes rows that are past their physical retention window so tables do not grow without bound. Postgres-native (Post-B Phase 1): queries use explicit ``$n`` placeholders on Postgres and ``?`` on SQLite — no reliance on ``db/dialect.py`` regex translation for this module.

Q: What does `backend/db/config.py` do?

A: Owns DATABASE_URL resolution and backend detection only.

Q: What does `backend/db/connection.py` do?

A: Async database connections for SQLite (default) and PostgreSQL (optional).

Q: What does `backend/db/correlation.py` do?

A: OTX pulses/IOCs, correlation suppressions, prioritization, asset matching. Split from database.py (Phase 3). Postgres-native (Post-B Phase 1): queries use explicit ``$n`` placeholders on Postgres and ``?`` on SQLite — no reliance on ``db/dialect.py`` regex translation for this module.

Q: What does `backend/db/cve.py` do?

A: CVE CRUD, embeddings, related-CVE lookups, and the shared change-row helpers upsert_cves needs. Split from database.py (Phase 3). Postgres-native (Post-B Phase 1): queries use explicit ``$n`` placeholders on Postgres and ``?`` on SQLite — no reliance on ``db/dialect.py`` regex translation for this module.

Q: What does `backend/db/embeddings_pgvector.py` do?

A: pgvector / embeddings helpers (E1 migrate + E2 write path). Copyright © 2026 Sai Harsha Vardhan SPDX-License-Identifier: Apache-2.0

Q: What does `backend/db/embeddings_search.py` do?

A: pgvector ANN + keyword helpers for related CVEs and hybrid search (E3). Related uses stored vectors only (no request-path inference). Semantic search embeds the query once when ``EMBEDDINGS_ENABLED=1`` (design §7.1); bulk ML sweeps remain scheduler-only. Copyright © 2026 Sai Harsha Vardhan SPDX-License-Identifier: Apache-2.0

Q: What does `backend/db/embeddings_store.py` do?

A: Runtime read/write for the multi-entity ``embeddings`` table (E2/E3). Dual-writes with legacy ``cve_embeddings``. E3 related/search prefer this table (pgvector ANN on Postgres; BLOB cosine on SQLite). Copyright © 2026 Sai Harsha Vardhan SPDX-License-Identifier: Apache-2.0

Q: What does `backend/db/enrichment.py` do?

A: Enrichment: KEV/EPSS updates, change history, display-field backfills. Split from database.py (Phase 3). Postgres-native (Post-B Phase 1): queries use explicit ``$n`` placeholders on Postgres and ``?`` on SQLite — no reliance on ``db/dialect.py`` regex translation for this module.

Q: What does `backend/db/errors.py` do?

A: App-level database exceptions — dialect-neutral replacements for sqlite3/asyncpg types. Post-B Phase 2: callers outside ``db/`` must catch ``DatabaseError`` / ``DatabaseLockedError``, not ``sqlite3.*`` or ``asyncpg.*``.

Q: What does `backend/db/explorer.py` do?

A: Read-only DB explorer queries — parameterized, allowlist-only.

Q: What does `backend/db/explorer_registry.py` do?

A: Read-only DB explorer allowlist — deny-by-default table registry. Only tables listed here are browsable via /api/admin/db-explorer/*. Column names, filters, and ORDER BY clauses are static; user input never becomes SQL fragments.

Q: What does `backend/db/init.py` do?

A: DB init/bootstrap: get_db, init_db, run_postgres_migrations. Split from database.py (Phase 3). Postgres-native (Post-B Phase 1): runtime fixup SQL is dialect-neutral (no placeholders); SQLite bootstrap DDL in ``init_db`` is not translated. Postgres schema is applied via Alembic in ``run_postgres_migrations``.

Q: What does `backend/db/integrity.py` do?

A: Database integrity checks — SQLite PRAGMA vs PostgreSQL pg_catalog probes.

Q: What does `backend/db/ioc_watchlist.py` do?

A: Per-user IOC watchlist (V1.5 Theme 4b).

Q: What does `backend/db/metadata.py` do?

A: MITRE ATT&CK/ATLAS technique + case-study metadata, AI/ML context, analytics. Split from database.py (Phase 3). Postgres-native (Post-B Phase 1): queries use explicit ``$n`` placeholders on Postgres and ``?`` on SQLite — no reliance on ``db/dialect.py`` regex translation for this module.

Q: What does `backend/db/outbound_jobs.py` do?

A: Read helpers for Procrastinate job rows (admin list). Postgres only.

Q: What does `backend/db/pg_adapt.py` do?

A: PostgreSQL SQL adaptation for legacy SQLite-oriented query strings. Internal to ``db/connection.py`` — routers and auth repos still emit ``?`` / ``datetime('now')`` SQL; ``PostgresConnection`` translates at the boundary. All ``db/*.py`` modules use native ``$n``/``?`` constants directly (Post-B Phase 1).

Q: What does `backend/db/resource_metrics.py` do?

A: Resource utilization samples — storage and retention (RB-1).

Q: What does `backend/db/search_tokens.py` do?

A: Search service API tokens (Embeddings E5) — bcrypt at rest, show-once plaintext. Copyright © 2026 Sai Harsha Vardhan SPDX-License-Identifier: Apache-2.0

Q: What does `backend/db/software_catalog.py` do?

A: software_catalog persistence + autocomplete (Q3).

Q: What does `backend/db/stack_backfill.py` do?

A: Stack Tier-A backfill runs / checkpoints / ETA (Q4).

Q: What does `backend/db/sync_state.py` do?

A: Generic sync-state key/value store plus NVD watermark helpers. Split from database.py (Phase 3). Postgres-native (Post-B Phase 1): queries use explicit ``$n`` placeholders on Postgres and ``?`` on SQLite — no reliance on ``db/dialect.py`` regex translation for this module.

Q: What does `backend/db/threatfox.py` do?

A: ThreatFox IOC mirror table (V1.5 Theme 4b).

Q: What does `backend/db/timeutil.py` do?

A: Shared UTC timestamp helpers for DB writes.

Q: What does `backend/db/txn_boundaries.py` do?

A: Transaction boundaries between SQL work and outbound source I/O. Postgres ``command_timeout`` (``DATABASE_POOL_COMMAND_TIMEOUT_SECONDS``) is a **single shared budget for SQL statements** on pooled connections. Feed/source HTTP timeouts are independent and intentionally different per API (CIRCL ~25s, Sploitus ~30s, ThreatFox ~120s, Nuclei/ExploitDB ~180s, …). Never nest source HTTP/DNS latency inside an open write transaction: concurrent jobs wait

Q: What does `backend/db/types.py` do?

A: Shared database connection types.

Q: What does `backend/db/user_notifications.py` do?

A: Per-user in-app notifications — analyst watchlist + operator alerts.

Q: What does `backend/db/watchlist.py` do?

A: Watchlist CRUD. Split from database.py (Phase 3). Postgres-native (Post-B Phase 1): queries use explicit ``$n`` placeholders on Postgres and ``?`` on SQLite — no reliance on ``db/dialect.py`` regex translation for this module.

Q: What does `backend/db/webhooks.py` do?

A: Webhook alert dedupe, delivery log, destinations. Split from database.py (Phase 3). Postgres-native (Post-B Phase 1): queries use explicit ``$n`` placeholders on Postgres and ``?`` on SQLite — no reliance on ``db/dialect.py`` regex translation for this module.
