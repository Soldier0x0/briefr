Backend · scoring & detection

Scoring, detection, matching, enrichment, brief.

What it does

Q: What does `backend/brief/service.py` do?

A: Server-computed morning brief (read-path only, no ingest).

Q: What does `backend/detection/artifact_extract.py` do?

A: LLM artifact extraction for DetectionContext (Track K4). Extracts structured ``{paths, params, keywords, method}`` artifacts from CVE description text and exploit metadata. Scheduler-side only — never on the request path. Uses the multi-provider LLM router (Groq → Cerebras → OpenRouter → Gemini).

Q: What does `backend/detection/backlog.py` do?

A: KEV-driven detection backlog (V1.5 Theme 3). Copyright © 2026 Sai Harsha Vardhan SPDX-License-Identifier: Apache-2.0

Q: What does `backend/detection/class_queries.py` do?

A: Class-keyed SIEM query and log-pattern templates (Sprint D3). Parallel to CWE Sigma templates — used when no ATT&CK technique is mapped.

Q: What does `backend/detection/class_router.py` do?

A: Unified detection class router (Sprint D3). Single resolution path for CWE/ATT&CK → stable class slug used by ``sigma_generator``, ``siem_queries``, and log-pattern output.

Q: What does `backend/detection/composer.py` do?

A: Evidence-composed detection pack (DC-1) + emission (DC-2). Retrieves CVE-grounded community rules, Nuclei/context artifacts, and YARA observables, then emits Sigma/SIEM/YARA from that pack. No LLM.

Q: What does `backend/detection/context.py` do?

A: DetectionContext scaffold (Sprint D2). Static CVE envelope cached in ``feed_cache`` for scheduler-built detection metadata. No LLM on this path — D4 adds artifact injection later.

Q: What does `backend/detection/context_llm_sync.py` do?

A: Scheduler-side LLM enrichment of DetectionContext artifacts (Track K4).

Q: What does `backend/detection/context_nuclei_sync.py` do?

A: Scheduler-side Nuclei artifact enrichment for DetectionContext (Sprint D4).

Q: What does `backend/detection/context_sync.py` do?

A: Scheduler-side DetectionContext backfill (Sprint D2). Populates ``feed_cache`` keys ``detection_ctx:{cve_id}`` from CVE row metadata. Disabled by default; never runs on the request path.

Q: What does `backend/detection/nuclei_parser.py` do?

A: Deterministic Nuclei template YAML parser (Sprint D4). Extracts ``{paths, params, keywords, method}`` artifacts from Nuclei HTTP blocks without an LLM. Scheduler-side only.

Q: What does `backend/detection/rule_sources.py` do?

A: Detection rule source discovery. Priority: SigmaHQ community rules → Elastic detection-rules → optional BRIEFR template (only when no community hit and not generic — see composer). All results cached 24 hours per CVE via feed_cache table. GitHub token is optional but recommended (env: GITHUB_TOKEN). Gracefully returns empty lists if the API is unavailable or rate-limited. SigmaHQ rules are under Detection Rule License (DRL) 1.1 — commercial use i

Q: What does `backend/detection/siem_queries.py` do?

A: SIEM quick-search query templates for BRIEFR detection engineering. Covers Elastic KQL, Splunk SPL, Microsoft Sentinel KQL, and QRadar AQL. Placeholders use {{FIELD}} notation — analysts replace with actual field names. Common field name variations documented per platform in each query's `notes`.

Q: What does `backend/detection/sigma_generator.py` do?

A: Template-based Sigma rule generator for BRIEFR. One template per major ATT&CK tactic family. Generated rules are marked experimental with a BRIEFR confidence note.

Q: What does `backend/detection/sigmahq_index.py` do?

A: SigmaHQ local Postgres rule index — download, parse, upsert, watermark. Scheduler job ``sigmahq_index_sync`` (U2) calls :func:`sync_sigmahq_index`. Detect/Forge read paths (U3/U4) call :func:`find_index_rules_for_cve`. Postgres-native only. No LLM. Sigma rules only (DRL-1.1 attribution).

Q: What does `backend/detection/yara_generator.py` do?

A: YARA rule templates from OTX pulse file hashes (hash-led hunts).

Q: What does `backend/enrichment/cve.py` do?

A: Derive display fields from NVD/KEV/OSV source data (no LLM).

Q: What does `backend/enrichment/domain_validation.py` do?

A: Validate DNS hostnames for IOC domain lookups (ASCII + IDN/punycode).

Q: What does `backend/enrichment/ioc.py` do?

A: Product module backend/enrichment/ioc.py (ioc).

Q: What does `backend/matching/cpe.py` do?

A: CPE-based asset ↔ CVE version matching.

Q: What does `backend/scoring/asset_match.py` do?

A: Asset profile matching for legacy Risk v1.1b and environment relevance inputs.

Q: What does `backend/scoring/environment.py` do?

A: Environment Relevance tiers v1.0 — categorical, never folded into Threat (ADR-002).

Q: What does `backend/scoring/priority.py` do?

A: Operational Priority v1.2 — rule-based P1–P4 bands (ADR-002 + W3 EPSS + W5 exposure).

Q: What does `backend/scoring/risk.py` do?

A: BRIEFR Risk Score v1.1b — six weighted components including Momentum.

Q: What does `backend/scoring/ssvc.py` do?

A: SSVC outcome computation (Act/Attend/Track) parallel to OP — exposed on /risk as ssvc.outcome.

Q: What does `backend/scoring/threat.py` do?

A: Threat Score v1.0 — asset-independent exploitation credibility (ADR-002).
