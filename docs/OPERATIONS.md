## Purpose

Defines how BRIEFR runs in production, how **state and secrets** are managed, and how **new releases stay compatible** with existing systemd + nginx + cloudflared deploys.

---

## Production reference topology

```text
Internet  →  Cloudflare  →  cloudflared-briefr  →  nginx :80  →  uvicorn :8000
LAN       →  nginx :80  →  uvicorn (prefer 127.0.0.1:8000)

systemd:
  briefr-backend.service
  briefr-backup.timer (every 6h)
  cloudflared-briefr.service

Paths:
  Code:     /opt/briefr
  Database: /opt/briefr/backend/briefr.db (SQLite default) or PostgreSQL via DATABASE_URL
  Backups:  /var/lib/briefr/backups
  Secrets:  /opt/briefr/backend/.env
```

## Stable configuration contract

These env vars must remain supported across releases (defaults preserved):

| Variable | Purpose |
|----------|---------|
| `DB_PATH` | SQLite file location |
| `BACKUP_DIR` | Archive directory |
| `BACKUP_RETENTION_COUNT` | Max archives |
| `BACKUP_AGE_KEY_FILE` | age identity for archive encryption (empty = plaintext) |
| `BRIEFR_ENV` | `production` / `development` |
| `BRIEFR_ADMIN_API_KEY` | Optional admin route protection (interim until app login) |
| `ALLOWED_ORIGINS` | CORS |
| `GITHUB_TOKEN`, IOC keys | Optional enrichment |

**V2.0 adds:** `DATABASE_URL` (optional Postgres), `WALLBOARD_TOKEN`, webhook secrets.

**Rule:** never rename without deprecation period reading old + new.

## Backup policy

| Tier | Frequency | Mechanism |
|------|-----------|-----------|
| Scheduled | Every 6h | `briefr-backup.timer` or `briefr-pg-backup.timer` |
| Pre-update | Before deploy | `briefr-update.sh` / admin UI (V1.4) |
| Manual | On demand | CLI or admin UI |

**Archive contents:**

- **SQLite:** `briefr.db` (PRAGMA integrity-checked)
- **PostgreSQL:** `briefr.pgdump` (`pg_dump --format=custom`, verified PGDMP header)
- `.env` — ✅ **shipped (V1.2):** archives are `age`-encrypted (`briefr-*.tar.gz.age`, X25519 via `pyrage`). Key at `BACKUP_AGE_KEY_FILE` (default `/var/lib/briefr/keys/backup-age.key`, generated by `briefr-backup.sh` on first run) — **outside `BACKUP_DIR` (enforced)**, readable by the `briefr` user so startup auto-restore keeps working. Encryption protects off-site / at-rest copies — not a compromised host, which can read the key. Keep an off-host copy of the key  
- Manifest: integrity results (SQLite) or pgdump SHA-256 (Postgres), digests, reason, `backend`, encryption flag + recipient public key  

**Dead-man monitoring (V1.3):** `briefr-backup.sh` pings a healthchecks-style URL on success — silence becomes the alert, covering both backup failures and a dead timer.

**Retention:** count-based (`BACKUP_RETENTION_COUNT`) + optional max age (V1.4 admin).

**Restore:**

- CLI: `deploy/briefr-restore.sh`  
- Auto-restore on corrupt DB at startup (existing)  
- Admin wizard (V1.4) — same backend code path  

**Off-site:** optional rclone/S3 — operator responsibility; document in runbook.

## Log rotation

| Log | Rotation |
|-----|----------|
| **briefr-backend** | systemd journal + `journalctl` vacuum policy |
| **App file log (optional)** | `deploy/logrotate-briefr.conf` (V1.4) |
| **Backup run logs** | `/var/lib/briefr/backups/logs/` — size/count cap |
| **nginx** | OS logrotate — not managed by BRIEFR UI |
| **Webhook delivery log** | DB TTL purge ~90d (V1.4) |

**Container (V2.0):** JSON logs to stdout; optional file on volume; no dependency on `journalctl` inside container.

---

## Application logs in admin (V1.4)

- **Ring buffer:** in-process, last 500 `INFO+` JSON log lines (`structured_logging._RingBufferHandler`); no `journalctl` from the app.
- **API:** `GET /api/admin/logs` — admin-gated, refresh rate-limited; filters: `level`, `logger`, `request_id`, `category`.
- **Categories:** Application, Scheduler, Backup, Webhooks, Security (derived from logger name).
- **Redaction:** secret-like `extra` keys (`password`, `api_key`, `*_TOKEN`, etc.) stored as `[REDACTED]` in buffer entries.
- **UI:** Admin pane → **Application logs** — tail, filter, auto-refresh (10s), NDJSON export.
- Support pack export: health JSON + version + truncated logs (future)

## Performance & concurrency

| Rule | Reason |
|------|--------|
| **SQLite: uvicorn 1 worker** | Single writer |
| **Parallel HTTP** | `asyncio.gather` for RSS in scheduler job |
| **No heavy work on tab open** | Incidents feed from snapshot |
| **Postgres (V2.0)** | Connection pool; multiple workers allowed |

## Release compatibility rules

1. **Additive API** — new fields in `meta`; avoid breaking response shapes without version bump.  
2. **Forward-only migrations** — numbered schema migrations.  
3. **Auth opt-in tightening** — env flag before requiring auth on all reads.  
4. **CLI break-glass** — backup/restore scripts always maintained.  
5. **Defaults unchanged** — paths and ports unless migration doc provided.

## UFW / network hardening (operator)

Recommended end state (documented, not enforced by app):

| Port | Purpose |
|------|---------|
| 80 | nginx (LAN + cloudflared origin) |
| 22 | SSH (LAN only if possible) |
| — | No public 8000; uvicorn on 127.0.0.1 |

cloudflared requires **outbound** HTTPS only.
