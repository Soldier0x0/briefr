What was tried, shipped, and later reversed

Real decisions this codebase made and then deliberately undid — the most honest way to understand a system is to see what it tried and walked back, not just what it currently does.

The legacy admin-key header, replaced by real accounts (Spec A0, decided 2026-07-05). Before Chapter 11's login system existed, BRIEFR authenticated administrative access with a single shared secret header (X-BRIEFR-Admin-Key) — effectively one shared password for anyone who needed admin access, with no per-user identity, no audit trail of which admin did something, and no way to revoke one person's access without rotating the key for everyone. It was removed in favor of the full account system this book covers in Chapter 11 — individual users, roles checked live against the database, sessions that can be revoked per-account. This is worth reading as the clearest single example in this codebase of "we shipped the simple version first, learned its limits, and replaced it" rather than getting the design right on the first attempt.

Anthropic/Claude, removed from the LLM failover chain. Track K's own record states plainly: "No paid APIs — no Anthropic (removed from the chain for now)." Chapter 24 already established that BRIEFR's current LLM chain (Groq → Cerebras → OpenRouter → Gemini) contains no Anthropic client anywhere in the code — this entry confirms that's a reversal, not an oversight: a premium-tier provider was in the chain at some point and was deliberately taken back out, consistent with the project's stated goal of keeping a self-hosted tool's operating cost near zero. "For now" signals this is a scoping decision tied to the free-tier cost strategy, not a permanent technical exclusion.

db/dialect.py, a general SQL translation layer, deleted entirely (Post-B, 2026-07). Chapter 9 already covers what replaced it — paired _SQLITE/_PG query constants written by hand — but it's worth naming this explicitly as a reversal rather than just a current-state fact: a general-purpose translator that tried to make one SQL string work on both databases automatically was tried, and abandoned in favor of deliberately writing both dialects out by hand. The lesson embedded in that reversal: an automatic translation layer that almost works is more dangerous in a data layer than an explicit, slightly more verbose approach that always works.

Chart.js, reversal completed. Chapter 3's library registry now records the end state: Chart.js was deprecated in favor of Recharts, migrated page-by-page behind the shared chart shell, and then removed from package.json. Worth including here specifically because it shows what a healthy reversal looks like after the exit condition is met — the temporary coexistence does not linger as permanent dependency drift.

Self-check

  1. What specific capability did the legacy admin-key header lack that the current per-user system provides — name the exact gap, not just "it was less secure."
  2. Why might a project deliberately exclude a premium-tier LLM provider from its failover chain even if that provider would produce marginally better output?
  3. What made a general-purpose SQL dialect translator riskier than writing both dialects by hand — tie your answer back to Chapter 9's data-layer discussion.
