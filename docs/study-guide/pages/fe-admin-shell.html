Admin shell — sidebar, grids, ops pages

The operator control plane under pages/admin/: URL ?p= routing, shared sidebar/status chrome, and one page module per ops concern.

One router, many pages

AdminPage.jsx is the shell: it owns admin mode entry, sidebar selection synced to ?p=, and lazy mounts of the concrete pages (OverviewPage, FeedHealthPage, SchedulerPage, ApiKeysPage, AiOperationsPage, StoragePage, ResourcesPage, WebhooksPage, SecurityPage, DisplayPage, …). Sidebar.jsx + StatusBar.jsx are shared chrome; page modules stay focused on one ops job.

Health vs freshness, jobs, retrieval

FeedHealthPage.jsx is the canonical "circuit OK ≠ sync fresh" surface — operators need both. SchedulerPage.jsx surfaces job locks and progress while LOCKED. AiOperationsPage.jsx is where retrieval health (Chapter 24C) lands for humans. StoragePage.jsx includes the allowlisted DB explorer; WebhooksPage.jsx is the destination CRUD UI. Shared helpers under pages/admin/ (formatters.js, jobStatus.js, needsAttention.js) keep presentation consistent without copying logic into every page.

Density over marketing

Admin follows the same design-system rules as analyst: fill width, semantic tokens, shared grids — not a separate "admin theme." That is deliberate: operators live here under stress; inventing a second visual language would slow them down.
