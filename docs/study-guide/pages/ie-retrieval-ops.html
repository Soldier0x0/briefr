Part IV · Chapter 24C

Retrieval ops — health, auto-on-ingest, and honest degraded states

Embeddings are not "set and forget." After E1–E8 shipped, operators need a live picture of index health, pending work, and whether new ingest tails are embedding automatically — without loading the model on the request path.

services/retrieval_health.py routers/admin/ai_ops.py ml/embeddings.py pages/admin/AiOperationsPage.jsx

What "retrieval health" reports

GET /api/admin/retrieval/health (admin router) delegates to services/retrieval_health.py's build_retrieval_health(). The payload is ops honesty, not a search: embeddings enabled flag, auto_on_ingest, pgvector write posture, model name, whether the Postgres vector extension is present, live counts by entity type (CVE / technique / campaign), pending missing rows, last backfill summary, last ingest-tail summary, and a structured degraded reason (disabled, no_vector_extension, cold_index) when the index cannot serve semantic search meaningfully.

Importantly, this path does not load the embedding model. Counting and sync_state reads stay cheap enough for an admin panel poll.

Auto-on-ingest defaults on

EMBEDDINGS_AUTO_ON_INGEST defaults to 1 when embeddings are in play, still requiring EMBEDDINGS_ENABLED. Enabling embeddings (0→1) in admin config couples auto-on-ingest to on unless the operator explicitly sets auto off alone. Caps bound work (ingest max 25, backfill max 2000) so a sudden CVE flood cannot turn the scheduler into an unbounded embed storm. This is retrieval only — still no RAG chat.

Where operators see it

Admin → AI operations (AiOperationsPage.jsx) renders the health panel from the retrieval endpoint. Pair it with Chapter 24's hybrid search story: search reports which method served a query; retrieval health explains whether the index is even warm enough for semantic hits to be plausible.

Self-check

  1. Name three fields build_retrieval_health() returns that distinguish "feature on" from "index useful."
  2. Why must the health endpoint avoid loading the embedding model?
  3. What happens to EMBEDDINGS_AUTO_ON_INGEST when an operator flips embeddings from off to on in admin config?
