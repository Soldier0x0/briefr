System Design — the whole shape, in four diagrams

Everything else in this book zooms into one box from these pictures. Come back here whenever you feel lost about where a file fits.

1 — Overall architecture

One process, one database, five logical layers. The single rule that shapes almost everything downstream: nothing in the top two rows (browser, API routers) is allowed to do slow work — that's reserved for the scheduler row, which writes its results to the database for the API to read back cheaply.

2 — Request lifecycle: from a login to a CVE detail view

A concrete trace through Chapters 6 and 11: a login exchanges credentials for two cookies, then every later request rides on the short-lived one, with a silent refresh if it's expired. Notice the detail-view fetch fans out to reads only — nothing here computes a score or a correlation live, it all comes from tables the scheduler already filled in.

3 — The ingest & scheduling pipeline

How a CVE gets from CISA's servers into an analyst's browser, restated visually: everything left of the database is scheduler-only, everything right of it is the read-only API. The outbound queue is the one gate every external call passes through, in both directions of this pipeline.

4 — Deployment topology: what actually runs on the box

The reference production deployment (Chapter 32), matched exactly to the real nginx-briefr.conf and briefr-backend.service files in the repo — not a generic "here's how you'd deploy a web app" diagram.
