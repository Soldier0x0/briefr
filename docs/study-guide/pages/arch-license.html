Part 0B · Chapter A5

Why Apache License 2.0 — open source with built-in attribution

BRIEFR is OSI-approved open source under Apache 2.0. This chapter explains what that means for users and contributors — and why the project chose adoption over a commercial-use paywall.

LICENSENOTICECONTRIBUTING.md

What is on record today

The governing license is Apache License, Version 2.0 — LICENSE, NOTICE, CONTRIBUTING.md, and SPDX headers (SPDX-License-Identifier: Apache-2.0) on active source files. Earlier drafts considered proprietary terms, AGPL-3.0-or-later, and BUSL-1.1 before publication; those were reversed before external parties depended on them. The final choice fits BRIEFR's shape: a self-hosted analyst pane whose operators bring their own intel API keys — not a product whose revenue model is selling software licenses.

What Apache 2.0 grants — and what attribution means

Apache 2.0 is permissive: use, modify, distribute, and commercial self-hosting are allowed if you include the LICENSE, retain copyright notices, ship the NOTICE file, and document modifications. That is the built-in attribution — no custom license clause required. Apache 2.0 also includes a patent grant from contributors. It does not grant trademark rights to the BRIEFR name or logo.

What BRIEFR does not license for you

Open-sourcing BRIEFR does not open upstream intel. NVD, OTX, VirusTotal, AbuseIPDB, GreyNoise, SigmaHQ (DRL-1.1), and other feeds keep their own terms and quotas. Operators supply API keys and comply with each provider.

Self-check

  1. Name the files a redistributor must include alongside BRIEFR source.
  2. Can a for-profit company self-host BRIEFR under Apache 2.0 without paying the author?
  3. Why is Apache 2.0 a better fit than BUSL for a tool that depends on third-party API keys?
  4. Does Apache 2.0 grant trademark rights to use the BRIEFR name in a fork?
