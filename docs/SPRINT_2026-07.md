## Spec A0 — remove legacy admin key, enforce role (decided 2026-07-05)

Removal scope, verified by grep against code on 2026-07-04:

1. `backend/dependencies.py` — delete `require_admin_key` (verified: zero
   callers — already dead code) and the legacy branch of `require_admin`.
   New body:

   ```python
   async def require_admin(request: Request) -> dict:
       payload = await require_user(request)
       if payload.get("role") != "admin":
           raise HTTPException(status_code=403, detail="Admin access required")
       return payload
   ```

   Callers stay untouched: `routers/admin.py` uses it as a router-level
   dependency, `routers/refresh.py` calls it inline in five routes.
2. `backend/settings.py` — delete `briefr_admin_api_key`,
   `allow_legacy_admin_key`, and the `briefr_admin_api_key` validator.
3. `backend/main.py` — remove `"X-BRIEFR-Admin-Key"` from CORS
   `allow_headers`.
4. `backend/.env.example` — remove the admin-key lines.
5. **The key is runtime-rotatable — delete the whole rotation chain**
   (scope expanded after Gemini review of PR #260):
   - `backend/routers/admin.py` — `admin_key_set` in the security readout;
     `APPLY_ALL_EXTRA_KEYS = {"BRIEFR_ADMIN_API_KEY"}` (~line 94) and the
     matching exclusion in the single-key write path (~line 1090).
   - `frontend/src/pages/admin/SecurityPage.jsx` — the NOT-SET warning
     banner (~line 42), the ADMIN KEY StatCard (~line 55), and the
     **entire "Admin key" card including the Rotate flow** (~lines 59–89)
     — otherwise a dead Rotate button keeps writing a setting nothing
     reads. Update the page subtitle (mentions "admin-key status").
   - `frontend/src/api.js` — `setAdminKey`/`getAdminKey` (~line 389), the
     `X-BRIEFR-Admin-Key` header attachment (~line 400), and the
     legacy-auth comment (~line 409). `pages/admin/AdminPage.jsx`
     (~line 158) attaches the header in a raw fetch — the session cookie
     already flows; drop the header.
6. Tests. Header-auth tests switch to a session cookie:
   `test_admin_logs.py`, `test_rate_limit.py`, `test_webhooks_ssrf.py`.
   `test_admin_config.py` (~lines 94, 133) and `test_config_schema.py`
   (~lines 72–74) assert the rotation semantics — delete those assertions
   with the feature. A dozen admin test files
   `monkeypatch.setenv("BRIEFR_ADMIN_API_KEY", "")` as setup — remove the
   now-dead lines.
7. `audit()` in `dependencies.py`: catch `Exception`, not
   `sqlite3.OperationalError` — asyncpg errors are never sqlite3 errors,
   so on Postgres an audit-write failure currently 500s a valid admin
   action, exactly what the docstring promises can't happen.
8. New `backend/tests/test_security_invariants.py`, two parts:
   - Parametrized over **both** protected surfaces — the admin router's
     route table AND the five `/api/refresh*` routes (they call
     `require_admin` inline, so iterating only the admin router misses
     them): 401 with no cookie; 403 with an analyst-role token. New admin
     routes must be auto-covered (iterate the router, don't hand-list).
   - Separate single test against `POST /api/auth/login` only: the
     failure body is exactly "Invalid username or password" (admin routes
     return "Not authenticated"/"Admin access required" — do not
     parametrize this assertion over them).
9. Docs in the same PR: `PRODUCT_STATUS.md` "Interim admin" row,
   `API_REFERENCE.md` auth section, `routers/auth.py` docstring
   soak-window mention.

Pre-merge caveat: confirm nothing on the production box calls
`POST /api/refresh*` with `X-BRIEFR-Admin-Key` — check crontab and systemd
timers, not just the repo. If a machine consumer exists, migrate it first;
the future answer for machine access is scoped API tokens (only when a
real consumer appears), never a shared header key.

## Spec D1 — CWE→Sigma template mapping (design decided)

`cwe_ids` is already stored on `cves` (JSON list, e.g. `["CWE-22"]`) —
no ingest work needed. In `backend/detection/sigma_generator.py`:

1. Add `CWE_TEMPLATES: dict[str, dict]` keyed by CWE id, same shape as
   `TECHNIQUE_TEMPLATES`. Selection order in `generate_sigma_rule`:
   technique template → CWE template (first CWE with a mapping) →
   `DEFAULT_TEMPLATE`. Add a `briefr_basis` field to the rule output:
   `"attack_technique" | "cwe" | "generic"` so the UI can show why this
   template was chosen (PRODUCT.md principle 1).
2. Mapping table (validated starting set — extend, don't invent levels):

| CWE | Class | Logsource | Detection core | Level |
|---|---|---|---|---|
| CWE-22, -23, -35 | Path traversal | `webserver` | keywords: `../`, `..\\`, `%2e%2e%2f`, `%252e`, `/etc/passwd`, `boot.ini`, `web.config` | high |
| CWE-78 | OS command injection | `webserver` | keywords: `;id`, `|whoami`, `` `id` ``, `$(`, `&&+wget`, `;curl+`, `/bin/sh`, `cmd.exe+/c` | high |
| CWE-89 | SQL injection | `webserver` | keywords: `UNION+SELECT`, `' OR '1'='1`, `SLEEP(`, `BENCHMARK(`, `information_schema`, `xp_cmdshell` | high |
| CWE-79 | XSS | `webserver` | keywords: `<script`, `onerror=`, `javascript:`, `%3Cscript` | low (noisy; FP note mandatory) |
| CWE-502 | Unsafe deserialization | `webserver` | keywords: `rO0AB` (Java b64), `aced0005` (Java hex), `TypeObject`, `ysoserial`, `__VIEWSTATE` anomalies | high |
| CWE-94, -95 | Code injection / SSTI | `webserver` | keywords: `eval(`, `assert(`, `base64_decode(`, `{{`+`}}`, `${`+`}` template probes | medium |
| CWE-434 | Unrestricted upload | `webserver` | keywords: upload paths with `.jsp`, `.jspx`, `.php`, `.aspx`, `.ashx`, `.war` extensions | high |

# Zero-budget operating model

No paid API access is assumed. The loop:

1. **Specs over supervision:** judgment-heavy decisions get encoded in
   this appendix (or an ADR) once; Composer executes against them. If an
   item has no spec and needs a decision, write the decision down first.
2. **CI is the enforcer:** backend tests, Postgres job, audits, and the
   Playwright smoke run on every PR — an agent cannot merge red.
3. **Free reviewers on every PR:** the repo already uses Gemini review;
   keep it, and request a second free bot review where available. Bots
   catch mechanical issues; the specs catch design drift.
4. **Batch the strong-model sessions:** when a subscription session (like
   the one that produced this plan) is available, spend it on review of
   accumulated merged PRs + updating `docs/HANDOVER.md` + writing the next
   specs — never on typing code a spec could have delegated.
5. **Open-source flip unlocks free tooling** (Track F): most code-review
   and CI services are free for public repos.
