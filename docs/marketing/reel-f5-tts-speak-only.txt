BRIEFR is self-hosted CVE intelligence for security teams.

Every morning, see what changed in the last twenty-four hours. KEV deadlines, EPSS movers, and stack matches in one ranked queue.

Your declared stack comes first. CVEs touching Apache, Palo Alto, Citrix, or whatever you run bubble to the top with an explainable risk score.

Open any CVE for remediation status, patch availability, and a full threat picture.

Look up IPs, file hashes, and domains through VirusTotal, AbuseIPDB, and GreyNoise. Add free API keys when you want enrichment.

Generate a PDF report with triage snapshot, executive summary, and detection guidance.

Completely free, open source under Apache two point oh. Self-host on your own server. Two vCPU and two gigabytes minimum. Four gigabytes recommended with PostgreSQL.

# CUT 2 — SCORING & CORRELATION — 90s — briefr-cut2-scoring-correlation-90s.mp4
# Risk formula · stack matching · correlation · embeddings
# =============================================================================

How does BRIEFR decide what matters?

Every CVE gets a risk score from zero to one hundred. Six weighted factors. Asset match against your stack is the largest. Then CISA KEV listing, EPSS probability, exploit availability, CVSS, and momentum.

Same CVE, same stack, same score. Every time. Each factor includes a plain-English sentence explaining why.

Stack matching is term-based. Vendor and product strings from your profile against affected products in each CVE. Matches are labeled so you can judge them.

The correlation engine links CVEs that share OTX indicators, infrastructure, or campaigns. So you see clusters, not isolated tickets.

For semantic search, BRIEFR uses BAAI bge-small-en-v1.5 embeddings on CPU through fastembed. No GPU required. Find related CVEs by meaning, not just keyword overlap.

Scoring and correlation run on a fixed schedule. Your browser reads cached results. Fast triage, reproducible intelligence.

# Feed ingestion · Postgres 16 · pgvector · docker compose
# =============================================================================

Where does BRIEFR data come from, and where does it live?

A background scheduler ingests NVD, CISA KEV, EPSS, MITRE ATT and CK, AlienVault OTX, ExploitDB, OSV, SigmaHQ, and more. Public feeds are free. IOC enrichment uses optional free-tier API keys for VirusTotal, AbuseIPDB, and GreyNoise.

Everything lands in one PostgreSQL sixteen database. Intel tables and app tables in separate schemas. The scheduler writes. The API reads. No microservices, no separate message queue.

For production, use the pgvector image. Docker compose up, set your database URL, and you have vector-enabled Postgres for embeddings and the SigmaHQ rule index.

Minimum hardware: two vCPU, two gigabytes for local SQLite development. Recommended: two vCPU, four gigabytes with PostgreSQL for a small team deployment.

One deployment. Your data stays on your server. Generous free API limits for personal use and small teams.
